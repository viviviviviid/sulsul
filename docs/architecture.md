# 구조

```text
페이지 텍스트 ↔ content.js ↔ background.js
                                │ Chrome Native Messaging
                          sulsul-host.exe
                                │ stdin/stdout
                            host.mjs
                                │
                         ProviderRouter
                   ┌────────────┴─────────────┐
             Antigravity CLI            HTTP 제공자
             공식 Google 로그인       Gemini / OpenAI / Claude / Ollama
```

`content.js`는 렌더링된 텍스트와 열린/닫힌 Shadow DOM을 읽습니다. 링크와 코드 위치를 유지하도록 문단을 텍스트 조각으로 나눕니다. 원문과 적용된 번역을 함께 추적하여 사이트의 변경과 술술 자체 변경을 구별합니다. 번역은 `textNode.data`에만 적용합니다.

`background.js`는 같은 탭·출처의 읽기 세션, 취소, 로컬 캐시, 네이티브 연결을 관리합니다. 페이지에는 제공자 설정이나 키를 주지 않습니다. 설정 저장 시 활성 세션을 먼저 일시중지하고 요청을 취소합니다. 본문의 이전 번역 결과를 비운 뒤 새 설정을 저장합니다.

`ProviderSettings`는 제공자별 모델·암호화 키를 저장하고 공개 가능한 상태만 반환합니다. 키 원문은 익명 파이프로 고정된 저장 프로그램에 전달합니다. Windows는 PowerShell/DPAPI, macOS는 Swift/Security/CryptoKit으로 Keychain에 보관한 키와 AES-GCM을 사용합니다. 명령 인자·환경 변수에 키를 넣지 않습니다.

`ProviderRouter`는 한 요청에서 사용할 설정을 고정합니다. 캐시 범위에는 프롬프트 버전, 설정 리비전, 제공자, 모델이 반영됩니다. 설정이 변경된 뒤 도착한 이전 범위의 요청은 거부합니다.

`providers.mjs`는 고정된 HTTP 엔드포인트, JSON 스키마, 종료 사유·응답 크기 검증을 사용합니다. 외부 도구를 제공하지 않으며 오류 본문은 그대로 전달하지 않습니다. HTTP 요청은 자동 재시도하지 않습니다. CLI Flash Low의 JSON 형식 오류만 같은 Antigravity 제공자의 Medium으로 한 번 재시도합니다.

`Launcher.cs`는 Chrome의 파이프를 Node에 연결하는 창 없는 Windows 프로그램입니다. 설치 중 Windows .NET Framework 컴파일러로 생성합니다. macOS는 설치 시 생성한 `sulsul-host` 스크립트가 절대 경로의 Node를 실행하며, 로그인은 Terminal에서 같은 전용 CLI 프로필로 실행합니다. 관리자 권한이나 상시 서버는 필요하지 않습니다. 호스트 이름 `com.sulsul.gemini`는 기존 설치 호환성을 위해 유지합니다.

## 번역 속도와 취소

`content.js`는 최대 네 묶음을 동시에 요청하고 먼저 도착한 결과부터 적용합니다. 첫 결과 전에는 묶음당 최대 4항목·1,800자를 목표로 합니다. 이후 현재 화면에 보이는 항목은 8항목·3,200자, 화면 밖은 18항목·7,000자를 목표로 묶습니다. 한 문단 내부를 추가로 자르지 않으므로 첫 항목 하나가 글자 목표를 초과할 수 있습니다. 페이지 제목·도입부·주변 문맥과 번역 프롬프트는 유지합니다.

`background.js`는 모든 탭이 공유하는 대기열에서 네 요청까지 실행합니다. `host.mjs`도 동시에 실행하는 요청을 네 개로 제한합니다. 중지·페이지 이동은 해당 탭의 대기 작업과 진행 작업만 취소하며, AI 변경은 모든 작업을 취소하고 종료를 기다린 뒤 저장합니다. 준비 중 취소된 작업도 이후 AI로 보내지 않습니다.

연결 테스트도 같은 대기열에 들어가 번역과 실행 슬롯을 공유합니다. `settings-get`의 `maxConcurrentTranslations`와 확장의 상한 4 중 작은 값을 사용합니다. 이전 호스트가 2를 반환하면 두 요청까지만 실행하고, 이 필드가 없거나 유효하지 않으면 한 번에 하나만 보냅니다. 확장과 연결 프로그램의 업데이트 시점이 달라도 호스트의 요청 제한을 넘지 않습니다.

번역 실패 후에는 자동 요청을 멈추고 `failed` 상태와 오류 말풍선을 표시합니다. 하단 버튼·팝업·단축키의 재시도는 일시중지를 거치지 않고 바로 새 읽기를 시작합니다. 하단은 평소 상태 버튼 하나만 표시하고 호버·키보드 포커스 시 동작을 펼칩니다. 우클릭 메뉴는 하위 메뉴 없는 `술술 번역` 하나이며 시작·재개로 연결합니다.

검증된 번역은 캐시 쓰기·용량 정리를 기다리지 않고 반환합니다. 최근 8개 결과는 메모리에서도 보관해 저장 완료 전 같은 요청이 오면 재사용합니다. 저장 실패는 화면 표시를 막지 않습니다. Chrome이 서비스 워커를 종료하기 전 쓰기가 완료되지 않았다면 그 결과는 다음 실행에서 다시 번역합니다.

네 요청을 겹쳐 보내는 것으로 처리량 개선을 기대하지만, 실제 모델의 동시 처리와 계정 한도에 따라 효과가 달라집니다. 동시 실행되는 CLI 프로세스와 메모리 사용도 늘어납니다. 작은 묶음은 첫 표시를 앞당기는 대신 요청 수와 반복되는 문맥·프롬프트 양을 늘립니다. 모델별 속도·품질은 별도 실측 대상이며, 모든 사이트의 DOM과 모델별 한국어 품질을 보장하지 않습니다.

## 속도 측정

콘텐츠 스크립트 실행 컨텍스트에서 `__sulsul.state().measurements`로 현재 읽기 세션의 수치를 확인할 수 있습니다. 본문과 URL은 측정 객체에 넣지 않으며 측정값을 디스크에 저장하거나 외부로 전송하지 않습니다.

| 값 | 의미 |
| --- | --- |
| `firstTextMs` | 읽기 시작 후 첫 번역 적용까지, 본문 안정화 대기 포함 |
| `viewportMs` | 결과 적용 시점의 화면 안 항목들이 처음 처리된 시간, 건너뛴 항목 제외 |
| `totalMs` | 수집한 작업의 마지막 완료 시간, 동적 내용이 추가되면 갱신 |
| `requests` / `cacheHits` | 요청한 묶음 수 / 캐시에서 반환한 묶음 수 |
| `batches` | 최근 20개 묶음의 항목 수, 캐시 여부, 왕복·적용 시간 |

각 묶음에는 대기열(`queueMs`), 설정·캐시 확인(`prepareMs`), 호스트 왕복(`nativeRoundTripMs`), 제공자 총 소요(`providerTotalMs`), 검증(`validationMs`), 시도 횟수(`attempts`)가 포함됩니다. CLI는 실행(`spawnMs`), 첫 stdout 출력(`firstOutputMs`), 최종 결과(`resultMs`), 프롬프트 길이(`promptChars`)도 측정합니다. 첫 stdout 출력은 초기화 이벤트일 수 있어 첫 번역 토큰 시간으로 해석하지 않습니다. 재시도 시 제공자 총 소요에는 모든 시도가 포함되고 CLI 세부 시간은 마지막 시도 기준입니다. 캐시 적중 시에는 이번 요청의 대기·준비·총 소요만 반환합니다.
