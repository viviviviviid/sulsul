# 구조

술술의 `content.js`가 페이지의 텍스트 노드를 수집하고 `background.js`가 Native Messaging으로 이 PC의 `host.mjs`에 요청을 보냅니다. 공식 Codex app-server가 ChatGPT 인증과 번역을 처리합니다. 검증된 결과를 텍스트 노드에 적용하여 링크와 서식을 유지합니다.

`content.js`는 현재 화면의 본문, 바로 아래 본문, 화면의 나머지 텍스트 순으로 요청합니다. 본문 표식이 없는 페이지는 글 분량·링크 비율·위치로 본문 영역을 추정합니다. 본문 요청이 진행 중이면 메뉴가 실행 슬롯을 먼저 차지하지 않도록 기다립니다.

`ProviderSettings`는 ChatGPT 모델과 Fast 설정을 저장하고 이전 제공자 선택을 ChatGPT로 전환합니다. 설정 리비전은 진행 중인 요청을 구분하며 캐시 범위는 번역 언어·모델·Fast 설정·프롬프트 버전으로 분리합니다. 같은 설정을 다시 저장해도 캐시는 재사용합니다. 이전 제공자의 키를 복호화하거나 사용하지 않습니다.

`background.js`는 요청 묶음과 문단별 캐시를 관리합니다. 문단 키는 원문·잠금 상태·출처·모델 설정을 포함하고 수집 ID와 묶음 순서는 제외합니다. 메뉴는 같은 출처에서 공유하고 본문은 문서 경로·쿼리·제목·절까지 구분합니다. 캐시가 없는 문단만 요청하고 결과를 원래 순서로 합칩니다. 검증에 실패한 문단은 캐시하지 않습니다. Chrome 로컬 저장소의 번역 캐시는 최대 약 3MB·1,500항목으로 제한하며 저장 시점이 오래된 항목부터 제거합니다.

account-runtime.mjs는 공식 npm 레지스트리에서 고정 버전 Codex를 다운로드하고 SHA-512를 검증합니다. data/accounts/codex/profile을 전용 인증 저장소로 사용합니다. 부모 프로세스의 API 키·인증 토큰·시작 훅은 전달하지 않습니다.

AccountLoginSession은 Codex의 로그인 완료 알림을 기다린 다음 인증 상태로 연결을 검증하며 AI 생성 요청은 보내지 않습니다. 사용자가 취소할 수 있고 10분 후 자동 종료합니다. 로그인 URL만 확장에 전달하고 토큰은 전달하지 않습니다.

번역 전 `account/read`에서 ChatGPT 인증을 확인합니다. 임시·읽기 전용 스레드, 외부 도구 비활성화, JSON 스키마와 문단 검증을 사용합니다. 요청별 스키마는 공백을 포함한 모든 번역 대상 텍스트 ID를 필수로 지정하고 잠긴 코드 조각은 제외합니다. 실패한 문단의 원문은 유지합니다. `turn/start`의 추론 수준은 `low`이며 Fast를 켜면 실행 설정에 `features.fast_mode=true`와 `service_tier="fast"`를 전달합니다.

Windows Launcher.cs는 Chrome과 Node의 파이프를 연결하며 콘솔 창을 열지 않습니다. macOS는 절대 경로로 Node를 실행하는 스크립트를 사용합니다. 기존 설치 호환성을 위해 Native Messaging 이름 com.sulsul.gemini와 확장 키를 유지합니다. 이 이름은 Gemini 요청을 의미하지 않습니다.

모든 탭은 최대 4개 요청 대기열을 공유합니다. 탭 중지·이동은 해당 작업만 취소하며 모델 변경은 모든 작업을 취소하고 종료를 기다린 뒤 저장합니다. 취소된 대기 작업은 전송하지 않습니다.

설치·배포는 scripts/files.mjs의 명시적 파일 목록을 사용합니다. 개인 설정·로그인 자료·다운로드된 계정 실행 파일은 배포물에 포함하지 않습니다.

## 요청 범위와 입력 캐시

현재 화면과 아래 두 화면까지만 미리 번역합니다. 긴 본문은 현재 화면에서 4~8개씩 처리하고, 바로 아래는 최대 12개·5,000글자, 그 다음 화면은 최대 24개·12,000글자로 묶습니다. 짧은 메뉴·제목은 최대 24개씩 모읍니다. 더 먼 내용은 스크롤로 가까워질 때 요청합니다. 숨겨진 탭에서는 새 요청을 멈추고, 이미 보낸 결과는 받아서 캐시에 저장합니다.

`host/core.mjs`의 `promptDocument()`는 페이지 전체 제목 목록·도입부·뒤 문단·페이지 URL·캐시용 메타데이터를 AI 입력에서 제외합니다. 참고용 앞 문단은 같은 구역에서 최대 280자씩, 요청당 합계 560자로 제한합니다. 페이지 주소와 캐시 메타데이터는 로컬 처리에만 사용하며, 번역할 원문 자체에 포함된 주소는 그대로 전달합니다.

Chrome의 번역 결과 캐시와 AI 서버의 입력 캐시는 별개입니다. 고정 지침은 앞부분에 일정하게 배치하지만, 현재 Codex 구독 연결에서는 캐시 키·보관 시간·캐시 경계를 직접 지정하지 않습니다. 캐시를 채우기 위한 별도 AI 요청도 보내지 않습니다. 서버의 재사용 여부는 제공자가 보고한 **캐시 읽기**로 확인하며, 0이면 해당 요청에 캐시 읽기가 보고되지 않은 것입니다. Input 합계에는 캐시 입력이 포함됩니다.

API의 입력 캐시 지원 조건은 구독 한도의 절감률을 보장하지 않습니다. [OpenAI 입력 캐시 문서](https://developers.openai.com/api/docs/guides/prompt-caching)

## 반복 요청 진단

`host/history.mjs`는 원문·문맥·모델 설정의 반복을 비교하기 위해 로컬 비밀키로 HMAC 식별값을 만듭니다. 원문이나 전체 URL을 그대로 기록하지 않으며, 설치마다 비밀키가 달라 서로 다른 PC의 식별값은 같지 않습니다.

사용 기록의 **이전 요청과 겹침**은 보관 중인 기록에서 같은 조합으로 다시 요청된 문단 수입니다. 재시도·캐시 삭제 후에도 겹칠 수 있어 곧바로 오류를 뜻하지 않습니다. CSV의 요청 ID와 문단 묶음 식별값으로 요청을 비교할 수 있습니다. 업데이트 이전 기록은 비교할 수 없습니다.
